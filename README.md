# 飞书 AI 助手「水蜜桃桃」

把一个能读代码、能跑命令、能自己动手干活的 AI Agent，接到飞书里。

不是"定时发通知的机器人"——是一个跑在 DSH（DeepSeek Harness）里的**持久会话**，有工作区、有工具、有记忆，能连续多轮把一个任务做完。群里 @ 它、私聊它，它自己派子 agent 去查日志、读代码、分析现场问题，然后把结果推回来。

---

## 它长什么样

```
   飞书云端（群消息 / 私聊 / @提及 / 图片）
        │  ① WebSocket 长连接（出站，不需要公网 IP）
        ▼
   消息接收层（bot.py）—— 常驻进程，开机自启
        │  ② 只投递，不等回复
        ▼
   桥接层（dsh_bridge.py）—— 本机 HTTP
        │  ③ 回环访问
        ▼
   DSH 持久会话（人设 + 系统约束 + 记忆）
        │  ④ 自主调用工具：读文件 / 跑命令 / 分析日志 / 派子 agent
        ▼
   ⑤ agent 自己把结果推回飞书（push.py）
```

**一句话读法：消息进 → 交给 AI → AI 自己干活 → AI 自己把结果推回去。**

中间没有"等 AI 回复再转发"这一步。这是整套设计里最关键的一个决策——理由见下方「为什么不让 bot 转发回复」。

---

## 三个核心设计

### 1. 长连接，不是 webhook

飞书接入有两条路。webhook 要公网地址、要备案域名、要证书；长连接是我们的进程主动出站连飞书，**不需要公网 IP**。

选它的理由只有一个：这台机器就挂在一台办公电脑上，没有公网地址。

代价：长连接是单实例的。要做多实例或加 webhook 备份，必须补按消息 ID 去重——飞书会重投没及时确认的事件。

### 2. AI 的输出是初稿，出口必须有闸门

**这是整套系统里最重要的一条，也是治理决策不是技术决策。**

AI 会推测、会补全它不确定的东西、会在证据不足时给出看起来很肯定的结论。所以不能让"AI 想说什么就直接说什么"。

三层闸门：

| 层 | 手段 | 管什么 |
|---|---|---|
| 第一层 | 关掉 bot 自动转发 | AI 没有"想说什么就自动发出去"的通道 |
| 第二层 | 每次发送必须显式调用 | 发什么、发到哪，都得明确写出来 |
| 第三层 | 内容分级 | 对外结论必须人工定稿才能发群 |

技术上落到一句话：**谁产生内容谁负责交付。** bot 只做三件事——贴表情告诉用户"收到了"、把消息投递进去（投完就返回）、投递失败时说一声。**回复 100% 由 agent 自己推。**

> AI 可以自己想，但不能自己想完就直接对外说。中间那道闸门，是设计出来的。

### 3. 记忆按"什么时候需要"分层，不按内容分类

按内容分类（用户信息/项目信息/知识）是最容易想到的，但它**不告诉你该不该注入**——用户信息里，有的一句话都不能忘，有的一年用不上一次。

所以按使用时机分五轨：

| 轨 | 记什么 | 怎么进上下文 |
|---|---|---|
| **key** | 忘了会出事的硬性约定 | 每次自动注入（摘要形式） |
| **project** | 项目进展和踩过的坑 | 按需读取 |
| **user** | 用户的工作习惯和偏好 | 全量注入 |
| **daily** | 今天干了什么 | 按需读取 |
| **memory** | 跨项目通用事实 | 全量注入 |

判断标准一句话：**忘了会不会出事。**

**key 轨写入需要人工确认**——因为它进每一次对话，一条错规则会安静地污染之后所有行为，等同改生产配置。

## 文件说明

| 文件 | 作用 |
|---|---|
| `bot.py` | 消息接收层：长连接、解析消息、注入上下文、投递、心跳、调度 |
| `dsh_bridge.py` | 桥接层：把消息送进 DSH 会话（协议适配全在这一个文件里） |
| `push.py` | 推送：发消息到群/私聊，支持真实 @ 和引用回复 |
| `card.py` | 卡片消息：长任务进度原地更新，`with` 语句保证状态机有终态 |
| `recall.py` | 撤回消息：`--last` 默认只打印不撤，核对后加 `--yes` 才真撤 |
| `watchdog.py` | 看门狗：进程死/僵死双检测，自动拉起 |
| `config.py` | 配置加载（从 `.env` 读） |
| `start_bot.ps1` | 启动脚本，带防双开守卫 |
| `start_hidden.vbs` | 隐藏窗口启动 |
| `run_watchdog_hidden.vbs` | 看门狗隐藏启动（任务计划用） |
| `install_autostart.bat` | 安装开机自启 |
| `docs/` | 架构分享讲稿、技术附录、搭建手册 |

> **注**：`storage.py` / `reporter.py` / `group_summary.py` 等业务模块（消息流水、日报、群总结）属于本机业务逻辑，不在本仓库。`bot.py` 对它们做了容错——缺失时自动降级，消息照常收发，只是不做流水归档和日报。

## 快速开始

```bat
rem 1. 准备配置
copy .env.example .env
rem 编辑 .env，填 FEISHU_APP_ID / FEISHU_APP_SECRET

rem 2. 装依赖（本机 python 默认是 2.7，必须用 py -3）
py -3 -m pip install -r requirements.txt

rem 3. 启动
py -3 bot.py
```

### 飞书开放平台需要做

1. 创建企业自建应用，**开启机器人能力**
2. 申请权限：`im:message`（读消息）、`im:message:send_as_bot`（发消息）、`im:chat`（群信息）
3. **发布上线**并创建版本（不发布则收不到任何事件）
4. 事件订阅选**长连接模式**，订阅 `im.message.receive_v1`
5. 把机器人拉进群，或直接私聊

### 还要一个 DSH

本项目的 AI 侧依赖 DSH 持久会话。需要：
- 本机跑着 DSH（默认 `127.0.0.1:3080`）
- 配一个 `feishu-bot` agent preset，人设和系统约束写进去
- `dsh_bridge.py` 里的 `DSH_BASE` / `CREDENTIALS_FILE` 指向实际路径

详细步骤见 [`docs/搭建手册-从零复刻.md`](docs/搭建手册-从零复刻.md)。

## 后台运行与开机自启

**立即后台运行**：双击 `start_hidden.vbs`，无黑窗。

**开机自启**：双击 `install_autostart.bat`，把快捷方式放进启动目录。

**看门狗**（推荐部署）：任务计划程序每 5 分钟跑一次

```bat
schtasks /create /tn "FeishuBotWatchdog" ^
  /tr "wscript.exe E:\feishu-bot\run_watchdog_hidden.vbs" ^
  /sc minute /mo 5 /rl highest /f
```

**必须走 VBS 隐藏启动**——直接挂 `.bat` 会每 5 分钟弹一次黑窗。

**查看日志**：

```bat
powershell -Command "Get-Content E:\feishu-bot\logs\bot.log -Tail 20 -Wait"
```

## 踩过的坑（挑几个）

**飞书很多失败是静默的。返回成功 ≠ 事情做成了。**

| 坑 | 现象 | 根因 |
|---|---|---|
| 真实 @ 不生效 | 文本里写 `@某某`，对方收不到提醒 | 必须用富文本的 at 节点，节点里是用户标识不是名字 |
| 引用回复静默失败 | 发消息接口带 `reply_message_id`，返回成功但没引用效果 | 必须用 `/im/v1/messages/<mid>/reply` 接口，那个字段被忽略 |
| 撤错对象 | 想撤最后一条，撤了上一条 | 时间戳只告诉你"哪条最新"，不告诉你"哪条想撤" |
| 进程静默消失 | 日志无异常、无退出记录，死了 24 分钟没人发现 | 推送工具是独立进程，**接收端挂了它照样能发消息**，从外面看不出聋了 |
| 约束没生效 | 写了 11 条系统约束，实际一条没注入 | 常量定义了但**没有任何代码引用**，配置写了 ≠ 生效了 |
| 图片上传失败 | 传图报 SSL 断连，文本正常 | 公司网络限制 **>100KB 传输**，缩到 100KB 内即可 |
| 启动脚本带中文 | 双击没反应，日志也没记录 | PowerShell/cscript 按 GBK 读无 BOM 的 UTF-8 脚本，中文被撕碎 |

完整清单见 [`docs/分享-飞书AI助手架构.md`](docs/分享-飞书AI助手架构.md)。
