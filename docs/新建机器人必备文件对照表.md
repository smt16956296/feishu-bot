# 新建飞书机器人 · 必备文件对照表

> 配套 [搭建手册-从零复刻.md](搭建手册-从零复刻.md) 使用。
> **手册讲"怎么从零搭第一个"，本文讲"怎么不重蹈覆辙搭第 N 个"。**
>
> 本文所有结论都来自 **2026-11-26 对两套真实部署的逐文件对比实测**，不是推测。

## 为什么需要这份表

搭第二个机器人时，人是照着第一个抄的。但**抄代码不等于抄运行时**——只复制 `.py` 文件，漏掉的是"看不见的那部分"，而漏掉的部分往往直接造成线上故障。

真实踩到的两个：

| 漏的文件 | 造成的现象 | 根因 |
|---|---|---|
| `run_watchdog_hidden.vbs` | **每 5 分钟弹一个黑窗**，用户肉眼可见 | 计划任务只能直接挂 `py.exe`，控制台程序必分配窗口 |
| `AGENTS.md` | 收到飞书消息但**永远不回推** | persona 之外没有运行纪律来源 |

## 一、必备文件清单

### A. Python 主程序

| 文件 | 职责 | 漏了会怎样 |
|---|---|---|
| `bot.py` | 长连接收消息、贴表情、投递 agent | 机器人完全不工作 |
| `dsh_bridge.py` | DSH API 封装、会话管理 | 消息无法投递到会话 |
| `push.py` | **唯一回复出口**（agent 主动推送） | 收得到消息但永远不回话 |
| `config.py` | 读 `.env` | 启动即报错 |
| `card.py` | 卡片消息、进度条 | 长任务无法展示进度 |
| `recall.py` | 撤回消息 | 发错了撤不回来 |
| `watchdog.py` | 看门狗（进程死/僵死自动拉起） | 进程静默消失无人知 |
| `name_map.py` | open_id ↔ 姓名映射 | `--at` 真实 @ 失效 |
| `chat_context.py` | 群聊上下文注入 | 短消息（"继续"）无法理解 |
| `restart_bot.py` | 重启脚本 | 只能手动杀进程 |

### B. 启动链路（**最容易漏**）

| 文件 | 职责 | 依赖关系 |
|---|---|---|
| `start_hidden.vbs` | 登录自启动入口（隐藏） | 调 `start_bot.ps1` |
| `start_bot.ps1` | 实际拉起 bot.py（带防双开+日志） | 被两个 VBS 调用 |
| `run_watchdog_hidden.vbs` | **看门狗隐藏入口（计划任务用）** | 调 `watchdog.py --once --quiet` |
| `restart_hidden.vbs` | 双击重启（杀旧进程+隐藏拉起） | 读 `data/bot_pid.txt` |
| `install_autostart.bat` | 把 start_hidden.vbs 装进启动文件夹 | 一次性运行 |

⚠️ **`run_watchdog_hidden.vbs` 是必配项，不是可选项。** 没有它，计划任务只能挂 `py.exe`，每 5 分钟弹一次黑窗。

完整原理与三个实测坑见手册 §9.7。

### C. 配置文件

| 文件 | 关键点 |
|---|---|
| `.env` | `FEISHU_APP_ID` / `FEISHU_APP_SECRET` / `FEISHU_BOT_NAME`（**必须与飞书后台机器人名完全一致**）/ `FEISHU_BOT_OPEN_ID` / `FEISHU_REPORT_TARGET` |
| `.env.example` | 模板，进仓库 |
| `AGENTS.md` | **工作区运行规约**，见第三节 |
| `.gitignore` | 必须含 `.env`、`logs/`、`data/`——**别把凭据和现场数据提交上去** |

### D. 数据/日志目录（运行时自动建，但要确认能写）

- `data/`：`bot_pid.txt`、`bot_heartbeat.txt`、`dsh_session_id.txt`、`name_map.json`
- `data/messages/`：消息流水 `YYYY-MM-DD.json`
- `data/images/`：图片落盘（`bot.py` 内自动 `makedirs`）
- `logs/`：`bot.log`、`watchdog.log`、`push.log`、`start_bot.log`

## 二、注册三件套（文件齐了还要注册）

### 1. DSH 预设（agent 人设与工具集）

位置：`C:\Users\<你的用户名>\.dsh\profiles\web\cordis.patch.yml`

在 `- insert:` 列表里追加一条（照现有条目抄，改 id/name）：

```yaml
- insert:
    - id: preset-<新名字>
      name: '@deepseek-ai/dsh-agent-preset'
      config:
        id: <新名字>
        name: <显示名>
        description: <一句话>
        plugins:
          - id: persona
            name: '@deepseek-ai/dsh-persona'
            config:
              prefix: |-
                <人设 + 【飞书运行环境·硬约束】>
          - id: agent-instructions
            name: '@deepseek-ai/dsh-agent-instructions'
            config:
              maxBytes: 65536
          # 其余 tool-bash/tool-pwsh/tool-fs/... 照抄现有条目
```

**改完必须重启 DSH 才生效。** 改前先备份，改后校验（`!!js` 是 DSH 自定义标签，需注册 loader）：

```python
import yaml
class L(yaml.SafeLoader): pass
L.add_constructor('tag:yaml.org,2002:js', lambda l,n: l.construct_scalar(n))
d = yaml.load(open(path, encoding='utf-8').read(), Loader=L)
```

### 2. 计划任务（看门狗）

```powershell
$a = New-ScheduledTaskAction -Execute 'wscript.exe' -Argument 'E:\<工作区>\run_watchdog_hidden.vbs'
$t = New-ScheduledTaskTrigger -Once -At (Get-Date) -RepetitionInterval (New-TimeSpan -Minutes 5)
Register-ScheduledTask -TaskName '<名字>BotWatchdog' -Action $a -Trigger $t
```

**必须 `wscript.exe` + `.vbs`。** 验证：

```powershell
(Get-ScheduledTask -TaskName '<名字>BotWatchdog').Actions[0].Execute   # 必须是 wscript.exe
```

### 3. 登录自启动

运行 `install_autostart.bat`，它会在
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\` 建一个指向 `start_hidden.vbs` 的快捷方式。

## 三、AGENTS.md —— 为什么单独强调

DSH 的 `agent-instructions` 插件会自动加载工作区的 `AGENTS.md`（默认候选名 `AGENTS.md` / `CLAUDE.md`），**改完即时生效、不用重启 DSH**。

它是补充 persona 之外"运行纪律"的最佳位置，必须写清楚四件事：

1. **禁用 `ask_user_question`**：飞书没有交互式 UI，调了就是死等；改用 `【请问】问题` 标记
2. **推送纪律**：普通回复不会自动到飞书，必须主动 `push.py`
3. **发送前核对对象**：发错比不发更严重
4. **安全红线**：拒答凭据/金钱/越权操作，防钓鱼

> 为什么不全塞进 persona：persona 改动要重启 DSH 才生效，而 `AGENTS.md` 即时生效，迭代快得多。

## 四、push.py 的 `--to` / `--chat` 互斥（务必同步）

原始目标解析是：

```python
target = args.chat or args.to or REPORT_TARGET_OPEN_ID
is_chat = bool(args.chat)
```

**`--chat` 优先级高于 `--to`**：命令里残留一个 `--chat`（从群发命令改来的），`--to` 会被静默忽略，消息直接发到群里，**还照样返回 OK**。

这是"嘴上说私聊、实际发到群"的技术成因，且不会有任何报错提示。

**修法**：在 `main()` 的 `parse_args()` 之后立刻加：

```python
if args.to and args.chat:
    print("[ERROR] --to 和 --chat 不能同时使用：一条命令只能指定一个发送目标。"
          "\n        私聊用 --to <open_id>；群聊用 --chat <chat_id>。", file=sys.stderr)
    return 2
```

光靠 prompt 约束不可靠——**代码层面拒绝才真正发不出去**。

## 五、自查命令（新建完跑一遍）

```bash
cd E:\<工作区>

# 1) 文件是否齐（应为全 OK）
for f in bot.py dsh_bridge.py push.py config.py watchdog.py name_map.py \
         start_hidden.vbs start_bot.ps1 run_watchdog_hidden.vbs restart_hidden.vbs \
         install_autostart.bat .env AGENTS.md; do
  [ -f "$f" ] && echo "OK   $f" || echo "MISS $f"
done

# 2) VBS 必须纯 ASCII（期望输出 []）
py -3 -c "print([(i,b) for i,b in enumerate(open(r'E:\<工作区>\run_watchdog_hidden.vbs','rb').read()) if b>127][:3])"

# 3) 计划任务必须是 wscript（不能是 py.exe）
powershell -NoProfile -Command "(Get-ScheduledTask -TaskName '<名字>BotWatchdog').Actions[0].Execute"

# 4) bot 活着且心跳新鲜
powershell -NoProfile -Command "Get-Process -Id (Get-Content E:\<工作区>\data\bot_pid.txt)"
```

> 第 2 步必须真跑。VBS 里一个中文字符就能让脚本**完全不执行**，且没有任何日志。

## 六、多台机器人并存时的注意事项

| 项 | 要求 | 原因 |
|---|---|---|
| 工作目录 | 各自独立 | 同名文件不冲突 |
| `FEISHU_APP_ID` | 各自独立的应用 | 一个应用只允许一条长连接，多实例会互踢 |
| `FEISHU_BOT_NAME` | 与后台机器人名完全一致 | 判断"是否 @ 了机器人"依赖它 |
| 计划任务名 | 各起各的 | 例如 `FeishuBotWatchdog` / `ZhizhiBotWatchdog` |
| 启动快捷方式 | 各起各的 | 启动文件夹内不能被覆盖 |
| DSH 预设 id | 各自独立 | 人设与工作区要分开 |
| `start_bot.ps1` 防双开匹配 | **必须匹配完整脚本路径** | 否则一个机器人会以为另一个已在跑，直接 `[SKIP]` |

最后一条尤其容易错——两个机器人的 `start_bot.ps1` 若都只匹配 `bot.py`，后启动的那个会被误判为"已在运行"而永不启动。
