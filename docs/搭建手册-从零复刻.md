# 搭建手册：从零复刻一套飞书 AI 助手

> 面向：有 Python 基础、没接触过本项目的同事
> 目标：照着做完，你能有一套自己的「飞书群聊里 @ 一下就能干活的 AI 助手」
> 参考实现：`E:\feishu-bot`（下称"原项目"）。本手册所有命令和依赖均来自该项目的真实代码。

## 2. 飞书开放平台配置

### 2.1 建应用

1. 打开 <https://open.feishu.cn/app> → **创建企业自建应用**
2. 填写名称、图标、描述
3. **添加应用能力** → 勾选 **机器人**
4. 进入「凭证与基础信息」，记下 **App ID**（`cli_` 开头）和 **App Secret**（后面写进 `.env`，**不要贴到任何聊天里**）

### 2.2 开权限

「权限管理」→ 搜索并开通：

| 权限码 | 用途 | 必需 |
|---|---|---|
| `im:message` | 接收消息事件 | ✅ |
| `im:message:send_as_bot` | 以机器人身份发消息 | ✅ |
| `im:message.group_at_msg` | 接收群聊中 @ 机器人的消息 | ✅ |
| `im:chat` | 读取群信息（群名） | 建议 |
| `im:resource` | 下载消息里的图片/文件 | 建议 |
| `contact:user.base:readonly` | 查用户姓名 | 可选 |

> **不申请 `contact` 权限也能跑**——原项目就是用 `name_map.py` 从群消息的 @ 提及里自动学习 `open_id → 姓名` 映射的，从未 @ 过的人显示为 `成员_xxxxxx`。

### 2.3 事件订阅：长连接 vs webhook

| | 长连接（推荐） | webhook |
|---|---|---|
| 网络要求 | 只需出站，**不需要公网 IP / 证书 / 端口** | 需要公网可访问的 HTTPS 地址 |
| 部署位置 | 办公电脑、内网服务器都行 | 必须公网服务器 |
| 多实例 | 一个应用只允许一个长连接 | 天然支持多实例 |
| 配置复杂度 | 低 | 需要备案域名 + 证书 |

**选长连接**（原项目就是这么跑的）。

配置路径：「事件订阅」→ 订阅方式选 **使用长连接接收事件** → 添加事件：

- `im.message.receive_v1`（必需，收消息）
- `im.chat.member.bot.added_v1`（建议，被拉进群时自动登记）
- `im.message.reaction.created_v1`（可选，**订阅了就必须在代码里注册空处理器**，否则日志刷 `processor not found`）

### 2.4 发布

「版本管理与发布」→ 创建版本 → 申请发布 → 管理员审核通过。**没发布上线，机器人收不到任何事件。**

## 7. 接 DSH

### 7.1 前提

DSH 跑在本机 Web 模式，监听 `127.0.0.1:3080`。

### 7.2 要改的常量

全部在 `dsh_bridge.py` 顶部（第 23-29 行）：

```python
DSH_BASE = "http://127.0.0.1:3080/api"
SESSION_ID_FILE = "data/dsh_session_id.txt"
CREDENTIALS_FILE = r"C:\Users\<你的用户名>\.dsh\.credentials.yaml"
AUTHORITY = "127.0.0.1:3080"

DEFAULT_CWD = "E:/feishu-bot"      # agent 的工作区
AGENT_PRESET = "feishu-bot"        # DSH 里的 agent 预设 id
```

| 常量 | 改成 |
|---|---|
| `CREDENTIALS_FILE` | 你本机的 `~/.dsh/.credentials.yaml` 路径 |
| `DEFAULT_CWD` | 你的项目目录 |
| `AGENT_PRESET` | 你在 DSH 里定义的预设 id（见 7.3） |
| `AUTHORITY` | 若端口不同，改这里并同步改 `DSH_BASE` |

### 7.3 在 DSH 里定义一个 agent 预设

DSH 0.2.1 起，预设不再是 `~/.dsh/.agent-presets/<id>/` 目录，而是写在 profile 的 `cordis.patch.yml` 里，追加一段：

```yaml
- insert:
    - id: preset-your-bot
      name: '@deepseek-ai/dsh-agent-preset'
      config:
        id: your-bot              # ← 对应 AGENT_PRESET
        name: 你的助手
        description: 飞书机器人用的 agent 预设
        plugins:
          - id: persona
            name: '@deepseek-ai/dsh-persona'
            config:
              prefix: |-
                你是一个通过飞书机器人响应同事的助手。
                [系统约束] 1. 禁止调用任何需要用户交互的工具……
```

预设里至少要包含：`persona`（人设）、`agent-instructions`、`tool-pwsh`（Windows）、`tool-fs`、`tool-skill`、`tool-subagent`。

### 7.4 验证桥接

```bash
py -3 -c "import dsh_bridge; print(dsh_bridge.get_cursor(open('data/dsh_session_id.txt').read().strip()))"
```

返回一个整数（事件游标 seq）就说明鉴权和 RPC 都通了。返回 0 或报错，先查：

- DSH 是否在跑（`curl http://127.0.0.1:3080`）
- `CREDENTIALS_FILE` 路径对不对
- 预设 id 是否存在

### 7.5 系统约束一定要写

`dsh_bridge.py:202` 的 `SYSTEM_CONSTRAINT` 会随每条消息注入。最少要写这 5 条：

1. 禁止调用 `ask_user_question` 等交互工具（飞书没有 UI，调了就卡死）
2. 要提问就输出 `【请问】xxx` 文本标记
3. **完成后必须主动 `push.py` 推送**（回复不会自动到飞书）
4. 长中文先写 UTF-8 文件再 `--file`
5. 日报流水线请求不要推（流水线自己推）

## 8. 加记忆

### 8.1 分轨思路

| 轨 | 存什么 | 判断标准 |
|---|---|---|
| `memory` | 跨项目通用事实 | 所有项目都该知道 |
| `user` | 用户档案 | 关于人的（风格、偏好、边界） |
| `project` | 项目日志 | 要看时才查的进展与踩坑 |
| `key` | **硬性约定** | **忘了会出事的**，必须每次注入 |
| `daily` | 当天流水 | 今天干了什么 |

### 8.2 落地步骤

1. **`key` 轨只放"必须/禁止"**：推送约定、消息风格、安全红线、编码坑。不要放"发生了什么"。
2. **写入时机**：任务真正完成时，一次调用批量写 daily + project：

   ```
   memory(action=add, entries=[
     {target: "daily",   content: "..."},
     {target: "project", content: "..."}
   ])
   ```

3. **`key` 走人工确认**：`add` 进 `SUGGESTIONS.jsonl` 待确认队列，在 GUI 记忆页确认后才写进 `KEY.md`。因为 key 自动注入，一条错规则污染之后每一次对话。
4. **`project` 不需要归档**（本来就不注入）；`memory`/`user`/`key` 用 `archive` 把低频旧事移到 `*-archive.md`，**可逆**，GUI 里能移回。
5. **摘要模式**：key 每条自动生成一行 `[summary:...]`，提示词里只注入摘要，要用时 `memory(action=expand, id=...)` 展开全文。

### 8.3 人设

把完整人设写成 `data/persona_taotao.md` 存档，把**精简规则**放进 DSH 预设的 persona prefix。改人设 = 改预设 + 重启 DSH，不用改代码。

## 9. 开机自启

### 9.1 链路

```
启动文件夹 FeishuBot.lnk
   → start_hidden.vbs（cscript 无窗口运行）
      → start_bot.ps1（防双开 + 日志重定向）
         → py -3 -X utf8 bot.py
```

### 9.2 ⚠ 铁律：两个脚本必须纯 ASCII

`start_hidden.vbs` 和 `start_bot.ps1` 里**不能有任何中文字符**（注释、字符串、路径都不行）。

**原因**：`powershell -File` 和 `cscript` 读无 BOM 的 UTF-8 脚本时按 ANSI（GBK）解码，中文字节被拆散后可能构成引号或续行符，直接 `ParserError` / "缺少对象"，而且**没有任何日志**。

原项目实测踩过两次，启动失败的根因就是这个。

### 9.3 start_hidden.vbs（纯 ASCII）

```vbs
' Feishu bot background launcher (hidden window)
Set WshShell = CreateObject("WScript.Shell")
WshShell.Run "powershell -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File E:\feishu-bot\start_bot.ps1", 0, False
Set WshShell = Nothing
```

### 9.4 start_bot.ps1（纯 ASCII，带防双开）

```powershell
# Feishu bot launcher (guard against double-start + logging)
$log = "E:\feishu-bot\logs\start_bot.log"
$stamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
$existing = Get-CimInstance Win32_Process -Filter "Name LIKE 'py%' OR Name LIKE 'python%'" |
    Where-Object { $_.CommandLine -match 'bot\.py' }
if ($existing) {
    Add-Content -Path $log -Value "$stamp [SKIP] bot.py already running (PID $($existing.ProcessId -join ','))"
    exit 0
}
Start-Process py -ArgumentList "-3","-X","utf8","bot.py" -WorkingDirectory "E:\feishu-bot" `
    -RedirectStandardOutput "E:\feishu-bot\logs\bot_out.log" `
    -RedirectStandardError "E:\feishu-bot\logs\bot_err.log" -WindowStyle Hidden
Add-Content -Path $log -Value "$stamp [START] bot.py started"
```

两个关键点：

- **防双开**：两个实例同时连长连接会互相踢，消息可能丢
- **重定向日志**：不重定向的话 `pythonw` 裸跑 stdout 全丢，出故障完全不可查（原项目 2026-10-23 日报未推就是这个原因）

### 9.5 装到启动文件夹

**方式 A：脚本**（原项目的 `install_autostart.bat`）

```bash
install_autostart.bat
```

它会在 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup` 下创建 `FeishuBot.lnk` 指向 `start_hidden.vbs`。

**方式 B：任务计划程序**（更可控，推荐）

```powershell
schtasks /create /tn "FeishuBot" /tr "wscript.exe E:\feishu-bot\start_hidden.vbs" /sc onlogon /rl highest /f
```

好处：可以设"登录后延迟 1 分钟启动"（等网络就绪）、可以设"失败重启"。

### 9.6 验证自启

1. 注销/重启
2. 看 `logs/start_bot.log` 最新一行是不是 `[START] bot.py started`
3. 看 `logs/bot_out.log` 有没有 `connected to wss://...`
4. 再双击一次 `start_hidden.vbs` → `start_bot.log` 应出现 `[SKIP] bot.py already running`（说明防双开生效）

### 9.7 关闭

```bash
taskkill /F /IM pythonw.exe
```

（或用任务管理器结束对应的 `python.exe`）

## 11. 常见故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| 启动后没有 `connected to wss://` | App ID/Secret 错；应用未发布上线；长连接未开启 | 核对 `.env`；飞书后台确认"使用长连接接收事件"已选；重新发布版本 |
| 收不到任何消息 | 权限没开 `im:message`；事件没订阅 | 飞书后台补权限 + 补事件，然后**重新发布版本** |
| 群里的 @ 没反应 | `FEISHU_BOT_NAME` 与飞书后台机器人名不一致 → `at_bot=False` | 改成完全一致的名字，重启 bot |
| 日志刷 `processor not found` | 订阅了事件但代码没注册处理器 | 注册空处理器，或去飞书后台取消订阅该事件 |
| `日志乱码 / ParserError / 缺少对象` | 启动脚本里有中文（按 GBK 解码被拆坏） | 脚本改纯 ASCII；用 `py -3 -c "print(open('x.ps1','rb').read().isascii())"` 验证 |
| 双击启动无任何反应、无日志 | 同上；或 `py` 不在 PATH | 手工跑 `powershell -File start_bot.ps1` 看报错；确认 `py -3 --version` 可用 |
| 推送出去中文乱码/截断 | 中文内联在命令行参数里，被 ANSI 代码页拆坏 | 写 UTF-8 文件，`push.py --file <路径>` |
| 推 `@某人` 对方没收到提醒 | 用了纯文本 `@名字`，飞书不认 | 用 `--at 姓名`（自动转 post 富文本 at 节点）；看 stderr 有没有 `无法解析 @xxx 的 open_id` |
| `无法解析 @xxx 的 open_id` | `name_map.json` 里没有此人 | 让对方在群里 @ 一次该人；或直接 `--at ou_xxxx` |
| `[WinError 10061] 由于目标计算机积极拒绝` | DSH 没启动，或正在跑长任务时短暂拒连 | 确认 DSH 在跑；bot 会重试 3 次并给用户友好提示，稍后重发即可 |
| 桥接 401 | DSH 凭据轮换；`CREDENTIALS_FILE` 路径错 | 核对路径；`_call` 遇 401 会自动重签一次，持续 401 说明文件读不到 |
| `session/history` 方法不存在 | DSH 版本比桥接层新，协议改了 | 对照 `dsh_bridge.py` 顶部注释适配；把差异关在 `_call` 一个函数里 |
| 日报某个群"总结失败"但模型很快回完 | 事件正文路径读错（`user/message` 是 `data.content`，`assistant/message` 是 `data.message.content`） | dump 两种事件 JSON 对比结构；按 `group_summary.py` 的兼容写法读 |
| 日报死等满 600 秒才失败 | 同上，`prompt_seq` 定位不到 | 同上 |
| 日报内容重复/夹带旁白 | 总结会话被污染 | 删 `data/summary_session_id.txt` 重建会话 |
| 同一天收到多份日报 | 重复触发；`--dry-run` 漏加参数 | 检查 `data/summary_sent.json`；补跑用 `--force`；测试一律先 `--dry-run` |
| 日报混进好几天前的消息 | 补拉历史把跨天消息写进了当天文件 | 按 `ts` 实际日期过滤（`group_summary.collect_group_messages` 已修） |
| agent 回复跑到私聊里 | 用了旧版"代发"逻辑 | 确认 `send_message(wait_reply=False)`，回复由 agent 自己 `push.py --chat` |
| 用户收到两遍回复 | bot 代发 + agent 自推 | 同上，bot 只投递不代发 |
| 长回合回复只有开头一段 | 旧逻辑只取第一条 `assistant/message` | 同上，改异步投递 |
| 重启后 AI 忘了之前聊的 | `data/dsh_session_id.txt` 丢了 | 该文件就是会话 id，恢复它即可续上上下文 |
| 机器人反复重连 | 正常网络抖动，SDK 自动重连 | 无需处理；频繁到分钟级才查网络/代理 |
